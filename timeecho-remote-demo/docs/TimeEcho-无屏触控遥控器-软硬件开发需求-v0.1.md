## 2. 产品目标与范围

### 2.1 目标

1. 用户看着大屏完成浏览、进入、返回、暂停和调音量。
2. 同一操作区覆盖顺序阅读与二维焦点导航。
3. 碰卡后卡片可以离开读卡区，作品会话继续。
4. 基础浏览在关闭云语音、网络不可用但内容已缓存时仍可完成。
5. 触控误判、断连、加载失败不得导致意外切作品、自动确认或执行过期命令。

### 2.2 首发范围

必须包含：触控导航、实体按键、NFC 入口识别、BLE 配对重连、电量和充电状态、震动和状态灯、盒子会话管理、NODE 焦点适配、有限基础语音控制、已缓存内容播放。

首发不包含：飞鼠、手写、自由拖拽编辑、多指手势、任意网页完整控制、常开语音唤醒、遥控器独立内容浏览、未经确认的自动改稿。自由地图和三维连续操作另立需求。

## 3. 系统职责

| 模块 | 必须承担 | 不承担 |
|---|---|---|
| 遥控器 | 触控采样和手势判定、按键去抖、NFC 读取、语音采集传输、状态反馈、电源管理 | 下载作品、运行 NODE、直接读取卡内触点 Flash 歌曲 |
| 盒子会话服务 | 安全配对、输入路由、控制权、URL 校验、缓存和授权、语音意图、会话生命周期 | 将任意 NFC URL 直接授予系统权限 |
| NODE 运行时 | 焦点、顺序、进入返回、媒体控制、页面状态反馈 | 根据原始触控坐标各自重复识别手势 |
| 内容包/适配层 | 稳定节点 ID、阅读顺序、二维导航关系、媒体及可用能力 | 依靠视觉位置猜测内容关系 |

## 4. 硬件需求

### 4.1 外观与结构

| 编号 | 要求 | 验证方式 |
|---|---|---|
| HW-01 | 单手握持，拇指可到达导航、确认、返回与播放区；左右手均可使用 | 1:1 模型和真实任务测试 |
| HW-02 | 圆形固定触控面包含外缘滑动区与内侧四向点按位置；四向有浅凹/凸点等可触定位 | 盲定位和触控日志 |
| HW-03 | 中央确认是独立实体键，有明确行程和触觉分界；按压不能误触方向/环滑 | 连续按压、斜按、握持测试 |
| HW-04 | 返回、播放/暂停、音量使用实体键；按键图标和触感可区分 | 盲操测试 |
| HW-05 | 侧面语音键、读卡键可区分，正常握持和碰卡时不易误按 | 双手、翻腕和碰卡测试 |
| HW-06 | 背部上方设置有触感边界的非金属 NFC 区 | 各卡型和手持姿态测试 |
| HW-07 | USB-C 充电；充电时可操作；外部可执行维护复位，避免依赖失效触控恢复 | 充电操作及故障恢复测试 |
| HW-08 | 不配置显示屏；配置可控状态灯与震动执行器，语音采集期间有持续可见指示 | 状态一致性测试 |

尺寸可从原方案约 155×43×17 mm 起做模型，触控圆面尺寸须通过拇指覆盖测试决定。不得直接按效果图开模。

### 4.2 电子与电磁

- 触控支持外环位置、运动方向、连续性与四向区域判定；一块电容感应组件是优先路线，具体电极和控制器由电子验证确定。
- 外环“固定触控”与机械转盘必须在图纸、BOM 和固件命名中区分。若用金属饰件，不得未经验证覆盖感应区。
- 为触控校准、原始采样、噪声与误触原因保留调试接口；正式产品默认不保存用户触控轨迹。
- NFC 必须具备 Reader 能力；仅具备 NFC Tag 功能的主控不能替代 Reader。
- NFC 天线、触控电极、地平面、震动器、电池及无线天线协同布局，验证并发干扰；覆盖扫描、充电、震动和语音传输组合。
- 麦克风需适合手持近讲，避免侧键、确认键和震动机械噪声明显污染采集。
- 电池从 650 mAh 级方案评估，最终容量、保护、温升、充电及续航由结构空间和实测确定。
- 量产前完成目标市场适用的电池、充电、RF/EMC 等合规评估；本稿不指定未确认的认证清单。

## 5. 触控和按键交互规范

### 5.1 导航语义

| 输入 | 统一事件 | 默认行为 |
|---|---|---|
| 外环顺时针滑动一个逻辑步长 | `NEXT_ITEM` | 下一阅读项 |
| 外环逆时针滑动一个逻辑步长 | `PREV_ITEM` | 上一阅读项 |
| 四向区域点按 | `NAV_UP/DOWN/LEFT/RIGHT` | 按屏幕空间关系移动焦点 |
| 中央实体键按下 | `CONFIRM` | 执行当前焦点操作 |
| 返回键 | `BACK` | 关闭当前浮层/操作模式，否则返回上层 |
| 播放/暂停键 | `PLAY_PAUSE` | 切换当前音视频或连续导览的播放状态 |
| 音量键 | `VOLUME_UP/DOWN` | 调整系统指定音频输出的音量 |
| 主页键（建议） | `HOME` | 回内容库；遇未保存草稿先提示处理 |
| 读卡键短按 | `SCAN_REQUEST` | 开启或重新开启一次扫描窗口 |
| 语音键按住/松开 | `PTT_START/END` | 开始/结束语音输入 |
| 电源键短按（建议） | `STANDBY_TOGGLE` | 请求盒子待机/唤醒；电视联动按配置 |

### 5.2 手势识别与仲裁

必须遵守：

1. 四向点按仅在抬手并判定未形成滑动后触发；不得在落指时立即发方向事件。
2. 一次接触只能归属一种手势。判为环滑后，直到抬手不能再触发方向点按。
3. 外环触控为相对移动，落指位置不直接跳转到某个作品。
4. 在四向区起手并移动到外环时，必须满足明确的环滑条件才接管；其余模糊轨迹取消，不猜测确认。
5. 中央确认按下时取消尚未提交的触控点按，清除环滑残余步长；按住及释放防护期内不发触控导航。防护时间可配置。
6. 从休眠唤醒的首个触摸只唤醒，不移动焦点；释放后下一次触摸才导航，防止拿起误触。实体键唤醒后可执行本次按键，但必须通过会话路由和去重。
7. 不使用惯性滚动；抬手后不继续发导航事件。首发不做转速加速，先保证一项一项可控。
8. 方向长触首发不连发；长列表通过环滑浏览。音量实体键支持可配置长按连发。
9. PTT 按住期间屏蔽触控导航和新扫描请求；实体返回可取消本次语音。音量保持可用。
10. NFC 扫描期间屏蔽触控导航，返回可取消扫描；识别完成后要求触控释放再恢复，避免翻腕产生导航。

### 5.3 可配置参数

下列参数必须可配置、可记录版本，初值由交互原型测定，不在本稿伪定器件采样阈值：

- 触控区域半径、死区、四向边界与边界滞回。
- 点按最大时长、允许位移、环滑最小位移、圆周逻辑步长。
- 环滑方向反转阈值、噪声滤波、发事件速率上限。
- 实体键去抖、确认防护期、音量长按延迟与连发间隔。
- 湿手/大面积接触判定、充电噪声阈值、自动校准条件。

逻辑步长最终以“可准确切换一项”为标准；不能按机械转盘的物理刻度直接换算。

## 6. 页面与媒体行为

### 6.1 焦点模型

- 所有可操作项有稳定 ID、可见焦点和可达路径。进入页面必须有默认焦点。
- 转环按内容声明的阅读顺序移动；四向按显式邻接或规则化布局移动。无目标时保持原位，默认不环绕。
- 顺序阅读和空间焦点必须同步：四向选中作品后，下一次转环从该作品继续。
- 工具面板/弹窗打开时，输入限定在当前前台范围；转环在其中按控件顺序移动，不能穿透切换后台作品。
- 返回按“当前浮层 → 当前操作模式 → 作品 → 展厅/内容库”的实际层级处理；回到展厅恢复原焦点与滚动位置。
- 内容缺少二维导航信息时可降级为顺序导航，但必须明确支持范围；不得伪装为所有网页都能完整遥控。

### 6.2 作品和进度

- 展厅中确认作品：进入。作品查看中焦点在作品本体时确认：显示/隐藏介绍；焦点在工具上则执行工具。必须通过焦点样式让用户区分。
- 转环默认切作品/章节/曲目，不默认改播放进度或音量。
- 快进、缩放、平移仅在用户明确进入对应模式后启用；大屏持续提示模式及退出方法，返回退出并恢复浏览语义。
- 播放/暂停只作用于当前活动媒体；无媒体或连续导览时不产生隐含副作用。
- 讲解、视频、音乐统一管理音频焦点；切作品不得出现旧音轨继续叠播。

## 7. NFC 与作品会话

1. 首发以实体读卡键显式开启扫描，建议窗口约 5 秒；拿起自动扫描保留为试验项，默认关闭。
2. 读到卡立即给一次短震和短灯反馈，停止本次扫描，再将入口提交盒子。
3. 盒子按“校验入口 → 校验授权 → 准备缓存/网络内容 → 就绪 → 播放”处理，并在大屏区分各状态。
4. 卡片离开后会话继续，不推断卡片持续在场；同卡重复读取不得无故重启作品。
5. 当前无作品时，已授权且就绪的作品可进入；已有作品时，新卡先给切换确认，取消或失败保留旧作品。
6. 未知来源先确认；禁止将任意 URL 直接送入带系统权限的运行环境。校验方案、跳转及允许能力。
7. 私人内容仍需账号/家庭授权，卡片身份不自动等同于完整访问权限。
8. NFC 只传入口/身份，不传输触点 Flash 中的歌曲；未缓存内容不能承诺离线即播。
9. 扫描超时提示一次，并允许按键重试；内容下载必须可取消、有超时和明确失败原因，不能无限加载。

## 8. 状态灯与震动

下表为反馈语义要求；颜色、节奏和强度须统一成参数表。不可只靠颜色区分成功与失败。

| 状态 | 遥控器反馈 | 大屏/声音反馈 |
|---|---|---|
| 已读到入口 | 一次短震＋灯短亮 | 显示对应封面/准备状态 |
| 正在扫描 | 低干扰扫描灯节奏 | 可选扫描提示及取消入口 |
| 内容已就绪 | 可选区别于读卡的短灯反馈 | 展示作品；不重复播放“读卡成功” |
| 扫描失败/超时 | 区别于成功的灯节奏及可选震动 | 提示靠近卡背读卡区/重试 |
| 语音采集中 | 持续可见采集灯 | 录音状态与取消入口 |
| 语音处理中 | 与采集不同的反馈 | 处理状态，允许取消 |
| 未连接/重连中 | 明确但不持续打扰的节奏 | 连接恢复提示 |
| 低电量/充电/充满 | 独立定义，避免高频重复提醒 | 有屏时显示具体电量 |

- 触控有效导航须有短触觉反馈；定义为“输入已识别”，不等同于页面已执行。无目标时由页面给边界反馈。
- 页面执行结果与扫描、录音状态优先级高于普通导航震动，震动不得无限排队。
- PTT 采集灯与实际采集状态一致；无法保证指示时不得继续采集。
- 震动强度与关闭选项由盒子设置；关闭震动不能关闭必要的录音指示。

## 9. BLE 通信与输入协议

### 9.1 通道

至少区分控制/确认通道、状态同步通道和语音数据通道。语音流不得阻塞返回、暂停或取消。按键、环滑发送统一语义事件，不向普通作品暴露原始触控轨迹。

### 9.2 事件结构（接口提案，联调前冻结）

```json
{
  "protocol_version": 1,
  "device_id": "remote-xxx",
  "connection_epoch": "epoch-xxx",
  "seq": 1024,
  "uptime_ms": 238100,
  "context_token": "ctx-xxx",
  "type": "NEXT_ITEM",
  "payload": { "steps": 1 }
}
```

| 字段 | 规则 |
|---|---|
| `protocol_version` | 握手校验兼容性；不兼容时明确拒绝或协商降级 |
| `device_id` | 设备身份，不能单独用来证明授权 |
| `connection_epoch` | 每次连接重新生成，用于丢弃旧连接事件 |
| `seq` | 当前连接内单调递增，去重依据 |
| `uptime_ms` | 遥控器单调时间；不能直接与盒子时钟相减算延迟 |
| `context_token` | 盒子下发的当前路由上下文；作品/模态切换后更新，旧值事件丢弃 |
| `type/payload` | 固定枚举及有界参数；不允许任意脚本命令 |

盒子返回 `ACK(seq, status, reason)`，区分已接收、已执行、拒绝和过期。状态同步含电量、充电、扫描、语音、活动控制权及反馈指令。

### 9.3 可靠性

- 控制消息以有序可靠方式传送；必要重试沿用原 `seq`，接收端保证最多执行一次。
- 导航消息设置有限有效期与队列长度；过期丢弃，不能在加载结束后突然连续跳页。
- 断连立即终止语音采集并清除待发导航、按住态和手势；重连重新握手，不补放旧操作。
- 作品或模态切换采用上下文屏障：更新令牌、清除残留手势，等待释放后接收新触控。
- 一次仅一位活动主控；其他遥控器请求接管，公共场景需授权。备用遥控器须可恢复基础使用。
- 配对必须经物理/屏幕确认；具备删除绑定和恢复出厂机制，不允许附近设备静默接管。

## 10. 语音与隐私

- 仅按住 PTT 时采集，松开立即停止采集；松开后可继续处理已采数据。禁止常开监听。
- 首发指令优先：上一件、下一件、返回、播放、暂停、音量调整；明确支持词表及对应页面条件。
- 低置信度、歧义或当前内容不支持时，显示选择/不支持原因，不猜测执行修改。
- 处理可取消；用户取消、切作品、失联后的旧结果不得再执行。
- 云语音可关闭，关闭不影响实体操作。离线可识别哪些命令必须按实际实现公布，不承诺完整离线语音。
- 普通 PTT 控制输入不得直接保存成作品录音。录音创作另需显式模式、预览和确认，默认私有。
- 语音不写入普通调试日志；保存、上传和保留期限需有明确用户授权与产品策略。

## 11. 关屏音乐辅助模式

- 首次网络与输出设置允许依赖电视；不要求首发提供完整无屏设置。
- 用户配置独立音频路径后，音乐卡可以不唤醒电视，支持切曲、暂停、音量和新卡切换。
- 已缓存且授权有效时可离线播放；未缓存、授权失败、网络失败时用简短声音说明，不要求用户理解灯码。
- 无屏下新卡切换使用明确声音提示及实体确认/返回；反馈声音应能通过配置的音频路径播放。
- 电视关闭后 HDMI 能否持续出声必须实测；3.5 mm 线性输出需接有源音箱/功放，不能描述为盒子自带扬声器。
- 不为该辅助模式增加曲名屏、独立内容库浏览或复杂播放列表。

## 12. 电源、维护与诊断

- 触控、NFC、点灯及震动按状态启停；NFC 禁止无期限扫描。
- 分别测待机、日常阅读、高频碰读、语音及充电使用功耗，再确定续航承诺。
- 低电量策略须保证不会在无法显示状态时继续录音；欠压进入安全关闭，避免反复重启。
- 盒子需处于支持接收唤醒的待机状态；完全断电不承诺 BLE 唤醒。
- 固件可更新、校验完整性，更新中断有恢复路径；提供不依赖触控的维护入口。升级传输和恢复方案在电子选型后冻结。
- 日志至少记录固件/协议/触控参数版本、事件序号、判定类别、拒绝原因和链路耗时；避免记录私人 URL 令牌和语音正文。

## 13. 验收标准

以下为建议立项目标，尚无样机实测证明。量产阈值在交互样机和 EVT 后冻结；P95 为 95% 样本不超过该值。

| 编号 | 测试 | 建议通过标准 |
|---|---|---|
| QA-01 | 无说明首次碰读，覆盖左右手、大小手与所有计划卡型 | 至少 20 名目标用户，首次独立完成率 ≥95%；分卡型/姿态报告，不只汇总 |
| QA-02 | 盲操方向、确认、返回、暂停 | 至少 20 人，每人各类任务重复测试；单步正确率目标 ≥95%，记录低头次数与混淆 |
| QA-03 | 环滑只切一项、反向切换、环滑转点按 | 每种轨迹至少 100 次；单步准确率目标 ≥95%；无额外确认事件 |
| QA-04 | 握持、翻腕、碰卡、放下及拿起 | 至少 200 次动作，无误确认或误切作品；非预期导航率单独统计 |
| QA-05 | 中央确认与触控隔离 | 连续/斜向按压共 500 次，无额外方向或环滑事件 |
| QA-06 | 链路响应 | 盒子已醒、BLE 已连，输入到大屏反馈 P95 ≤100 ms；固件识别/传输/渲染分段记录 |
| QA-07 | 已缓存内容首帧 | P95 ≤2 秒，明确内容规模及计时起点为盒子收到有效入口；冷启动/公网下载另报 |
| QA-08 | 连续浏览 | 50 次进出节点、切卡、返回，无焦点丢失、白屏或旧音轨残留 |
| QA-09 | 断连、重连、消息重试及切上下文 | 注入重复/延迟/乱序事件；无重复执行、旧指令补放和旧语音执行 |
| QA-10 | 并发干扰 | 充电＋触控、NFC＋握持、震动＋触控、语音传输分别及组合测试；达到相同功能标准 |
| QA-11 | 语音隐私 | 松开、取消、断连和故障均停止采集；采集灯与真实状态一致 |
| QA-12 | 环境与兼容性 | 干手/微湿手、不同握持、电源噪声、全部目标卡型及电视/音响矩阵；公布限制 |
| QA-13 | 关屏音乐 | 选定音频连接矩阵下，关电视仍可播放和控制；失败原因可听懂并可恢复 |
| QA-14 | 失去遥控器/触控失效 | 备用配对遥控器或 USB 键盘等受支持方式可恢复播放、配对和维护 |

20 人测试用于方向判断，不足以证明全部用户群和长期可靠性。耐久、跌落、ESD、温升、寿命及产线测试由结构/电子补充正式计划。

## 14. 开发交付与阶段出口

| 阶段 | 必须交付 | 进入下一阶段的条件 |
|---|---|---|
| 交互原型 | 可调参数触控样机、真实 NODE 样例、输入日志；机械方案作为对照可选 | 证明环滑与四向能区分、盲操可用、确认不串扰 |
| 电子可行性 | 电极/RF 布局、器件路线、功耗预算、BOM、充电和并发干扰报告 | NFC 与触控在实际壳体和握持下稳定 |
| EVT | 遥控板、结构样、固件、BLE 协议、盒子和 NODE 完整链路 | QA 核心交互、异常与隐私项通过 |
| DVT | 可靠性、电视/音响/卡型矩阵、续航、合规计划、更新恢复 | 参数和结构冻结，无阻塞问题 |
| PVT | 配对写号、触控校准、NFC/按键/麦克风出厂测试及维修流程 | 良率、追溯和供应商成本确认 |

各团队最低交付：

- 工业/结构：尺寸、握持模型、按键触感、NFC 窗口、充电和维修结构。
- 电子：原理图、PCB/电极/天线、BOM、功耗、干扰、保护和调试点。
- 固件：手势状态机、参数表、按键/NFC/PTT、协议、电源和维护恢复。
- 盒子：配对控制权、消息去重/上下文屏障、会话缓存授权、音频、语音与反馈。
- NODE：内容能力清单、焦点规范、返回恢复、模态和媒体语义、至少一份覆盖全部控件的验收作品。
- 测试：可复现任务、日志、P50/P95、错误分类、恢复路径与未覆盖环境。
